# React 工作台改造记录

目标：用 React + TypeScript + Vite 实现助手、设备、工单三个页面，复用 FastAPI、LangGraph、SQLite 和 Milvus，并验证设备查询到工单保存的完整流程。

## 2026-10-20 · 第一步：工作台 API

- 新增带当前会话模拟状态和一跳关系的设备详情接口。
- 设备列表增加编号/型号搜索和受校验的分页参数；搜索使用参数绑定。
- 新增当前会话正式工单列表；待确认草稿和其他会话工单不混入列表。
- 页面和模型工具共用设备事实查询，保持场景由服务端注入。
- 验证：`python -m pytest -q` 返回 17 passed，含新增的场景隔离、未知设备、搜索分页和工单列表隔离测试；1 条已有依赖弃用警告。

## 2026-10-20 · 第二步：React 工作台

- React + TypeScript + Vite，使用 React Router、Tailwind CSS 和 shadcn/ui 的按钮、徽标、输入框、文本框组件。
- 助手页：消息、资料来源、工具查询摘要、会话恢复、工单草稿。
- 设备页：站点/类型筛选、编号/型号搜索、分页、状态快照和一跳关系；带设备上下文进入助手。
- 工单页：当前会话列表、详情及刷新恢复；编辑草稿后必须保存当前版本再确认。
- 写操作使用前端互斥状态；旧版本冲突时重读服务端草稿；页面读取请求使用 AbortController 防止过时请求覆盖。
- HTML 输出保持 React 文本转义，资料链接仅允许 HTTP/HTTPS。

## 2026-10-20 · 第三步：构建与验证

- FastAPI 提供构建产物和已知页面路由；未知 API 保持 404，缺少构建时明确提示 503。
- `start.ps1 -BuildFrontend` 安装锁定依赖、构建并启动；Node 依赖、缓存、构建产物和数据库不提交 Git。
- 浏览器回归覆盖设备到工单的完整流程、未保存修改、旧版本冲突、取消、空数据、失败重试、窄屏和案例切换。
- 浏览器回归通过 `tests/workbench_server.py` 使用临时 SQLite 和模型测试替身；真实模型调用另行核验，不能把两者混为一谈。
- SSE 属于后续扩展，当前继续使用完整 JSON 响应。
