## 3. app：运行时核心代码

| 文件 | 主要内容 | 输入、输出及关联 |
|---|---|---|
| `app/__init__.py` | Python 包标识文件 | 使 `app` 可以按包导入，不承担业务流程 |
| `app/config.py` | 加载 `.env`、确定项目与运行目录、数据库路径、模型连接配置 | 被数据库、模型与脚本共同读取 |
| `app/db.py` | SQLite 连接与事务辅助、建表、模拟数据初始化、会话和页面消息存取 | `init_db()` 建表；`seed()` 按固定规则初始化设备；数据写入 `business.db` |
| `app/tools.py` | 定义并包装允许模型调用的工具；实现参数化资产/状态/关系查询 | 设备工具访问 SQL；资料工具调用 `rag.py`；工单工具调用 `tickets.py` |
| `app/rag.py` | Embedding 子进程管理、Milvus 入库和查询、设备类型与型号范围过滤 | 入库：片段→向量记录；检索：问题→相关正文、元数据与分数 |
| `app/graph.py` | LangGraph 状态与模型/工具循环，调用预算、异常处理、引用 ID 核对、检查点保存 | 接收会话 ID 和用户消息，返回回答、工具记录、检索依据和当前草稿 |
| `app/tickets.py` | 工单字段校验、生成草稿、修改/取消/确认、版本检查、事务与重复确认处理 | 读写 `ticket_drafts`、`tickets`、`ticket_devices` |
| `app/main.py` | FastAPI 入口、启动清理、HTTP 接口、请求参数校验、同会话并发限制、静态网页服务 | 网页请求进入这里，再分派给 Agent、数据库或工单模块 |
| `app/static/index.html` | 网页结构：聊天、设备列表、依据和草稿区域 | 浏览器加载的页面 |
| `app/static/style.css` | 颜色、排版、布局、窄屏适配 | 只负责展示样式 |
| `app/static/app.js` | 原生 JavaScript：发 HTTP 请求、恢复会话、渲染消息/依据/设备、处理工单按钮 | 连接网页与 `main.py` 的接口；当前没有 React 或 Vue |
| `app/__pycache__/` 等同名缓存目录 | Python 自动生成的字节码缓存 | 不必阅读或手工修改 |

### tools.py 中的工具名称

| 名称 | 做什么 |
|---|---|
| `find_sites` | 按站点名或城市查询站点 |
| `find_devices` | 按站点、区域、类型、编号分页查询设备资产 |
| `get_device_status` | 查询当前会话所选模拟场景下的设备状态 |
| `get_device_neighbors` | 查询一跳上联或控制器管理关系 |
| `search_knowledge` | 检索资料，不查询实时设备事实 |
| `prepare_ticket_draft` | 保存待确认草稿，不创建正式工单 |
| `get_ticket` | 查询当前会话的正式工单 |

`device_search()` 是共用的资产查询函数，网页设备列表也会直接调用。`make_tools()` 根据当前会话构建上述工具。正式提交操作没有注册成模型工具。

## 4. scripts：单独运行的辅助脚本

| 文件 | 做什么 | 会产生什么或依赖什么 |
|---|---|---|
| `scripts/seed_data.py` | 调用 `db.seed()` 建表并填入固定模拟数据 | 初始化 `business.db`；已有设备时不会重新覆盖 |
| `scripts/fetch_docs.py` | 获取官方 FAQ，优先复用本地 HTML 缓存，提取正文与来源信息 | `data/raw/`、`data/docs/`、`source_manifest.json`、`fetch_errors.json` |
| `scripts/ingest_docs.py` | 读取正文，按段落与字符限制切分，生成元数据，再调用 `rag.ingest()` | `chunks.json`、Milvus 集合和 `runtime/index.json`；会同步项目集合的内容 |
| `scripts/embedding_worker.py` | 在配置的外部 Python 环境中加载本地模型，以 JSON 行协议接收文本并返回向量 | 由 `rag.py` 启动；CPU 编码，384 维，输入 token 上限 256；不负责直接写 Milvus |
| `scripts/evaluate_retrieval.py` | 用 5 个预设问题检查相关文档是否出现在前 5 条检索结果中 | `runtime/retrieval-evaluation.json`；需要真实 Embedding 与 Milvus，不是整体回答准确率评估 |
| `scripts/verify_core_live.py` | 通过 HTTP 验证真实模型、SQL、草稿、取消及普通应答不提交工单 | `runtime/core-live.json`；需启动后端并配置模型，会创建演示会话和草稿，不依赖 Milvus |
| `scripts/verify_live.py` | 验证真实 Milvus 检索、SQL 工具、引用、草稿、正式确认和工单查询 | `runtime/live-verification.json`；需后端、模型和 Milvus，会创建演示会话及正式本地工单 |

## 8. 三条最重要的调用路径

### 设备查询与资料问答

```text
app/static/app.js 发消息
  → app/main.py 接收 HTTP 请求
  → app/graph.py 调用模型
  → app/tools.py 执行模型选择的工具
      → app/db.py / business.db：设备、状态、关系
      → app/rag.py → embedding_worker.py + Milvus：资料
  → app/graph.py 将工具结果交回模型并生成回答
  → app/main.py 保存页面消息并返回
  → app/static/app.js 显示结果
```

### 正式工单提交

```text
网页确认按钮 → app/main.py → app/tickets.py
  → 校验当前会话、草稿版本和状态
  → 数据库事务保存工单和关联设备，标记草稿已提交
  → 返回正式工单编号
```

### 文档入库

```text
fetch_docs.py → data/raw/ + data/docs/ + 来源清单
ingest_docs.py 读取正文 → data/chunks.json
  → rag.ingest() → embedding_worker.py 生成向量
  → Milvus 保存向量、正文与元数据
  → data/runtime/index.json 记录入库信息
```
